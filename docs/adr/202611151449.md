# gemma（ローカル LLM）用の claude cli タイムアウトを延ばす

## ステータス

採用

## コンテキスト

`.claude/gemma-settings.json` で claude cli から LiteLLM 経由で Ollama の
gemma を使うと、長い入力の prefill に時間がかかる。キャッシュが効かない
約 44k トークン相当の入力をストリーミングで送ったところ、LiteLLM が
レスポンスヘッダーを返すまで約 137 秒かかった。LiteLLM は Ollama が最初の
トークンを出すまでヘッダーを返さないため、prefill の時間はそのまま
「ヘッダー待ち」になる。`num_ctx: 65536` いっぱいの入力や、Ollama が別の
リクエスト（サブエージェント等）を処理中で待たされる場合は、さらに延びる。

Claude Code のドキュメント（network-config「ストリーミングのアイドル
ウォッチドッグ」）によると、`ANTHROPIC_BASE_URL` でゲートウェイを使う場合、
ファーストバイト期限は実行されず、代わりに次のタイマーが効く。

- `API_TIMEOUT_MS`: レスポンスヘッダー受信までの制限。既定 600000（10 分）。
- ボディアイドルタイムアウト: ヘッダー待ちも含めて 5 分間バイトが届かないと
  中止。`API_FORCE_IDLE_TIMEOUT=0` でオフにできる。
- イベントレベル／バイトレベルのウォッチドッグ: ストリーム中に 300 秒
  イベントやバイトが届かないと中止。`CLAUDE_STREAM_IDLE_TIMEOUT_MS` で
  両方を設定できる（5 分未満は 5 分に引き上げ、バイトレベルは上限 30 分）。

既定のままだと、ヘッダー待ちが 5 分を超えた時点でボディアイドルタイム
アウトにより打ち切られる。

## 決定

`.claude/gemma-settings.json` の `env` に以下を設定する。Gemini 用の
`.claude/gemini-settings.json` は応答が速いため変更しない。

- `API_TIMEOUT_MS=900000`（15 分）: 65k トークン近い入力の prefill（推定
  3〜4 分）が、別リクエストの後ろで待たされる場合も見込んで 15 分とする。
- `API_FORCE_IDLE_TIMEOUT=0`: ヘッダー待ちを 5 分で切るボディアイドル
  タイムアウトをオフにし、ヘッダー待ちの上限を `API_TIMEOUT_MS` に一本化する。
- `CLAUDE_STREAM_IDLE_TIMEOUT_MS=900000`（15 分）: ストリーム中の無通信の
  打ち切りも同じ 15 分にそろえる。

## 影響・リスク

- Ollama が本当に固まった場合でも、claude cli がエラーにするまで最大 15 分
  待つ。待てない場合は Esc で中断する。
- auto mode の安全判定（約 60 秒で打ち切り）はこれらの変数では延びない。
  gemma では auto mode を使わない（README.md 参照）。
- LiteLLM 側のリクエストタイムアウトは明示しておらず、LiteLLM の既定値の
  ままである。
