# メッセージロギングを有効化

## ステータス

承認済み

## コンテキスト

デフォルト状態では `LiteLLM_SpendLogs` テーブルの `response` /
`proxy_server_request` カラムは常に空（`{}`）で、docker のアクセスログにも
リクエスト/レスポンス本文は出力されない（`messages` カラムは
realtime 系の呼び出し以外では常に `{}` のままで、今回のような通常の
`/v1/messages` 呼び出しでは使われない）。そのため、claude cli 経由で
実際にどんなやり取りをしたかをあとから確認する手段が無かった。
デバッグ・動作確認のため、会話内容を確認できるようにしたいという要望が
あった。

## 決定

`config.yaml` に以下を追加し、メッセージ本文のロギングを有効化する。

```yaml
general_settings:
  store_prompts_in_spend_logs: true
```

## 影響・リスク

- プロンプト・応答の本文が**平文のまま** Postgres の `LiteLLM_SpendLogs`
  テーブル（`response` / `proxy_server_request` カラム）に保存される
  ようになる。DB に誰かがアクセスできれば会話内容がそのまま読める状態に
  なるため、機密情報・個人情報を扱う用途では無効化を検討すること。
- 溜まったログを消したい場合は `scripts/purge_message_logs.sh` を実行する
  （`LiteLLM_SpendLogs` テーブルを全削除する）。
