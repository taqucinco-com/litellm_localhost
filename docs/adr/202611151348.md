# Ollama のローカル LLM を gemma4-26b-a4b-q4k として追加する

## ステータス

採用

## コンテキスト

ホスト上で Ollama によるローカル LLM（`gemma4-26b-a4b-q4k`）がすでに
稼働している。Gemini API の無料枠を消費せず、またネットワーク外にプロンプト
を送らずに、同じ LiteLLM Proxy の `/v1/messages` から LLM を使いたい。

当初は `gemini-3.5-flash-lite` の転送先を Ollama に差し替える案も検討したが、
モデル名と実体が食い違い、ログや UI 上で区別がつかなくなる。Gemini も
引き続き使えるようにしておきたいため、別モデルとして並べる方針にした。

## 決定

- `config.yaml` の `gemini-3.5-flash-lite` は Gemini API のまま残し、
  `model_name: gemma4-26b-a4b-q4k` を新たに追加して Ollama に転送する。
  クライアントはリクエストの `model` で切り替える。
- `ollama/` ではなく `ollama_chat/` を使う。Ollama の `/api/chat` を叩く
  ため、claude cli が使う tool calling やマルチターンの messages がそのまま
  扱える。
- LiteLLM はコンテナ内で動くため、`api_base` は
  `http://host.docker.internal:11434` とする。Docker Desktop では
  `host.docker.internal` がホストの localhost に届く（Ollama は
  `127.0.0.1:11434` で listen しているが到達できることを確認済み）。
  Linux の Docker Engine でも動くよう `extra_hosts` で `host-gateway` を
  明示する。
- gemma4 は thinking 対応モデルで、既定では思考に `max_tokens` を使い切り
  `text` が空のまま `stop_reason: max_tokens` になりやすいため、
  `litellm_params` に `think: false` を指定して無効化する。
- `litellm_params` に `num_ctx: 65536` を指定する。Ollama のモデルは
  Modelfile の `PARAMETER num_ctx 8192` で作成されており、超えた入力は
  黙って切り捨てられる（Ollama はあふれた分を捨てる際に約半分を残すため、
  届くのは 4099 トークン前後になる）。claude cli で
  試したところ `prompt_tokens` が毎回 4099 で頭打ちになり、ツール定義が
  モデルに届かず `shell` という存在しないツールを呼ぶ・宣言だけして実行
  しない、といった挙動になった。65536 にすると約 44k トークンの入力でも
  `Bash` ツールが正しく呼ばれることを確認した。モデル自体は 262144 まで
  対応するが、KV キャッシュのメモリと prefill 時間を抑えるためこの値にする。
  リクエスト側の `num_ctx` は Modelfile の値より優先されるため、Modelfile を
  作り直さず LiteLLM 側の設定だけで済ませる。

## 影響・リスク

- ホストで Ollama が起動していないと `gemma4-26b-a4b-q4k` へのリクエストは
  失敗する（Gemini 側には影響しない）。
- ローカル実行のため、長いプロンプトの初回 prefill は遅い（約 44k トークンで
  100 秒程度）。claude cli の応答が Gemini より大幅に遅くなる。
- Ollama 側でモデル名を変えた場合は `litellm_params.model` を合わせて
  `litellm` コンテナを再起動する。
