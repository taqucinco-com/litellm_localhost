# LiteLLM Proxy 経由での Sonnet サブスクリプション認証利用は行わない

## ステータス

却下

## コンテキスト

`claude --settings .claude/gemini-settings.json` を使わずに済ませたい、
また claude cli 内で `/model` コマンドだけで Sonnet と Gemini を切り替え
たい、という要望があった。

調査の結果、以下の技術的制約が判明した。

- `ANTHROPIC_BASE_URL` を設定すると、Claude Code は認証方式として
  `ANTHROPIC_AUTH_TOKEN` 等の静的トークンを優先し、`claude login` に
  よる OAuth（Pro/Max サブスクリプション）認証は無視される。
- Claude Code の設定にはモデルごとに異なる `base_url` / 認証方式を
  紐づける仕組みが無い。LLM Gateway 設定はグローバルに 1 エンドポイント
  のみを指す。
- `/model` コマンドはモデル名の切り替えのみで、認証方式（base_url）は
  切り替わらない。

このため「`--settings` 無しで、かつ CLI 内で Sonnet（サブスクリプション
認証）と Gemini（LiteLLM Proxy 経由）を切り替える」ことを両立するには、
LiteLLM Proxy 側にも Sonnet を model_list として登録し、単一の
`ANTHROPIC_BASE_URL` に統一する必要がある。

その方法として、LiteLLM には `forward_client_headers_to_llm_api: true`
を設定することで、Claude Code が送る OAuth トークン（`Authorization:
Bearer <token>`）を Anthropic API へそのままパススルーする機能が存在し、
これを使えば API キー無しでも Sonnet を LiteLLM Proxy 経由で呼び出す
ことが技術的には可能だった。

## 決定

上記のパススルー方式は**採用しない**。

Anthropic は 2026 年 2 月、Free/Pro/Max プランの OAuth トークンは
Claude Code と Claude.ai 専用であり、それ以外のツール・サービス
（サードパーティ経由も含む）で使うことは Consumer Terms of Service
違反であると明確化した。2026 年 1 月には、サブスクリプションの OAuth
トークンをサードパーティツール経由で使っていたケースに対する規約執行
（アカウント停止等）の実例も報告されている。LiteLLM Proxy を経由させる
時点で「Claude Code 単体での利用」ではなくなるため、規約違反としての
アカウント停止リスクを負うことになる。

よって、Sonnet はこれまで通り `ANTHROPIC_BASE_URL` を設定しない素の
claude cli（Anthropic 直結、サブスクリプション認証）で使い、Gemini を
使いたい時だけ `claude --settings .claude/gemini-settings.json` で
明示的に切り替える運用を継続する。

## 影響・リスク

- `--settings` オプション無しでの利用、および claude cli 内での
  Sonnet/Gemini 切り替えは実現しない。
- 今後 Anthropic 側の規約が変わった場合（例えば API キーを別途契約する
  等）は本決定を見直す余地がある。
